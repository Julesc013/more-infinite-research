# Player source boundary

This directory contains the MIR5 player-source implementation under development. It now includes authored modern and historical research, native continuations, effective settings, bounded compatibility bindings and product collection, opt-in prototype overrides, scripted effects, migrations, the Research Library and the data/runtime API. Complete retained-scope and final-package qualification remain pending. Do not package this README as a mod or use an unqualified development package to upgrade a production save.

Maintain these components using [the Generator contract](../spec/generator.md), [determinism](../spec/determinism.md) and the [API contract](../spec/api.md). Native imports and asset paths are package-relative and never contain the checkout prefix. Player code must not import the former compiler or developer SDK. The Generator validates the submitted finite family locally without recursion, then publishes once; compatibility collection and opt-in broad overrides remain separate.

Use disposable test worlds until the complete relevant catalogue and migration path are qualified. Earlier exact-source native receipts retain their original identities; they do not automatically qualify current bytes. The mechanical cutover is applied; this `source/README.md` remains package-excluded. Final-layout native qualification is recorded separately.

Build only this explicitly selected subtree with `python tools/package.py --source source --target <target> --output <canonical-name.zip>`. The tracked edition record selects one of nine targets and its actual engine capabilities; it is not another editable player source. Player packages contain only admitted native files and presentation assets. Read [current progress](../docs/progress.md) for accepted observations and remaining work, and [verification](../spec/verification.md) for the independent release verdicts. Offline packaging, host test counts and source size do not establish save safety or a native speedup.

The separate [early-edition record](../targets/early-editions.json) opts into best-effort F006–F012 data-only builds; those finite fixed defaults have no startup settings, control/runtime API, Library or migrations. F001–F005 and F018 remain unresolved as described in the [target contract](../spec/targets.md#additional-historical-editions). The authored [root changelog](../CHANGELOG.md) generates `changelog.txt`; every edition receives that complete shared history with its current distribution version substituted.
