# Contributor instructions

## Scope and authority

Read [the specification index](spec/README.md), then only the contracts and source required by the task. `source/` is the sole player-source root. `spec/` is normative; `docs/` explains it; tests provide independent expected behavior. Do not bulk-read historical releases or introduce a parallel architecture, request ledger or agent policy.

## Development

Normal reviewed implementation branches, pushes and PRs into `dev` follow standing maintainer authorization and required checks. `main`, tags, publication and external controls retain their separate authority. Never reset/clean away dirty work, force-push shared refs, move published tags or change branch/signing/release settings as a shortcut. Preserve unique local saves, logs and archives.

Each nontrivial task has one observable outcome, exact inputs, permitted files, independent expected behavior, actual test commands and a stop condition. No unrelated refactor, framework, new dependency or speculative API. Stop after the bounded result. Test-oracle changes require independent evidence.

## Product

Use authored research and native prototypes. The Generator performs small construction, not discovery or global planning. Preserve technology/settings IDs, tuning, earned effects, queues, runtime contributions, Library behavior and applicable target support. No partial development package on a production save. Keep developer tools/docs/SDK/evidence out of player ZIPs. Native bonuses have no recurring MIR tick work.

## Verification and resources

Run cheap affected checks first, then necessary native effect/save/client/performance scenarios. Reuse exact applicable receipts without relabelling them. Do not duplicate another worker's native job. Use at most three agent slots and one heavy native scenario per admitted machine. Preserve/restore test library controls. No game-engine downloads, Steam-depot mutation or replacement without current authority. A resource refusal or unrun test is not a pass.

## Delivery

Freeze accepted source and packages, complete required review/checks and promote through `dev` then `main`. Preserve the established numeric distribution encoding. Titles are `MIR MAJOR.MINOR.PATCH`; engine labels use actual patch floors, no `+`. Individual player ZIPs and useful integrity files are public; developer bundles are not default downloads. Verify anonymous bytes, matching local delivery and actual Portal status separately. A signature does not prove gameplay acceptance.

Report exact changes, commands/results, measured claims, gaps and the next bounded action. Never infer background execution from a checkpoint or model agreement.

## Determinism and bounded context

For ordering, runtime, migration or build changes read `spec/determinism.md` and the affected focused contract. Equal complete inputs must preserve semantic results; timing remains a measurement. Do not use elapsed-time budgets for gameplay work or infer current-save research in the data stage.

The public native API uses `api/v1/`, independently of product versions. Diagram assets are developer documentation. They never enter player packages or replace specifications. Root safety/release instructions retained from the predecessor remain binding until explicitly reviewed replacements exist.
