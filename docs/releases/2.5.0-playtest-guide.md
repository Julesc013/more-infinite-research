# MIR 2.5.0 Provisional Playtest Guide

Use only candidate `2.5-P3`, built from baseline `7ebe93029695bbf809a15a14c6540530738a9e62`, portable C16 source `0448ceb8d3992082718e2df83bd6a42c56955636`, and projection commit `dbb3e9e1519dc6f29326ca13ddb589550c66c2c7`. Before starting, require archive SHA-256 `86C6EE163CB393078E7E690C23800117324B40DB21F31BC4764A2797907E91EF`.

This is a provisional automated playtest candidate. Do not sign the release attestation, promote `tmp/2.0` to `legacy`, tag, seal, or publish it.

## Test Order

1. Start Factorio 2.0.77 with Base and the exact ZIP. Confirm startup, settings, technology tree, Steel research, effects, save, and reload.
2. Upgrade a copy of an MIR 2.4.9 save. Confirm research levels, fractional progress, settings, current research, and generated technology identities survive.
3. Repeat the supported official-DLC profile and inspect native owners, science packs, labs, prerequisites, and recipe targets.
4. Test Space Exploration, K2 2.0, K2 plus Space Exploration, and K2SO 2.0 as distinct exact closures. Verify K2SO ordering and science independently; do not infer it from the Factorio 2.1 result.
5. Test Angel, AngelBob, OC, BZ, and Py only with complete exact Factorio 2.0 dependency closures. A missing closure is missing input, not a compatibility pass.
6. Reproduce any issue in the smallest isolation ring before changing MIR.

## Candidate Review Modes

In SAFE mode, leave automatic technology creation off and require reviewed data. There must be no unwanted generated technologies. In PREVIEW mode, export the full catalog without mutations and build the human review queue. Use experimental creation only in a disposable save after reviewing the PREVIEW catalog.

Approve candidates individually. Record exact candidate, design, qualification, ecosystem, mod-version, settings, ownership, progression, balance, lifecycle, upgrade, removal, and migration evidence. Never promote every discovered proposal or interpret a diagnostic candidate as safe.

## Required Manual Surfaces

- Technology-tree layout and arrows.
- Icons and fallbacks.
- Locale fit, truncation, and right-to-left behavior.
- Settings UX and hidden-setting readability.
- Save UI, current research, and partial progress.
- Representative balance at early, middle, and late levels.
- Connected-player `give-item` behavior across configuration changes.
- Removed-recipe sanitation, including Py technologies whose source mod removes `casting-gear`.

Any package-visible tuning, promotion, metadata, locale, settings, migration, recipe, effect, or code change creates a new provisional 2.5 candidate. Rebuild and repeat candidate-bound evidence after batching accepted changes.
