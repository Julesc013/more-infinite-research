# MIR 2.5.0 P9 Playtest Guide

Use only candidate `2.5-P9`, built from baseline `7ebe93029695bbf809a15a14c6540530738a9e62`, portable C22 source `7ebe10dd52e34c8df54dc98dbc0f1375a134c4b8`, and Factorio 2.0 package source `f446d89f94ce4b9dc26f04c31c92f9bcffbac70d`. Require archive SHA-256 `30D7205527F3643169799AD8AF87C313D35DB81B14A6BDD460D9ED4D1B819DE3` before testing.

## Order

1. Base startup, technology tree, settings, save, and reload.
2. Official Factorio 2.0 DLC profile and concrete planet-discovery effects.
3. A copied MIR 2.4.9 save, preserving research, progress, settings, and generated identities.
4. The exact Factorio 2.0 Py closure, proving `casting-gear` is absent and `casting-mk02` retains only valid ordered sibling effects.
5. Maintained 2.0 ecosystem profiles, then large compatible stress profiles.

## Py acceptance

- `pypostprocessing`, `pypetroleumhandling`, and `pyrawores` are all enabled explicitly.
- The game reaches save creation.
- `casting-mk02` contains no unlock for missing `casting-gear`.
- Exactly the reviewed sanitation row is recorded; no unreviewed external effects are pruned.
- MIR-generated targets exist and science/lab reachability passes.

## Release boundary

Record observations against exact P9. Any package-visible correction creates P9. Automated evidence, the seven-item manual attestation, protected qualification, and the seal must all bind the same archive.
