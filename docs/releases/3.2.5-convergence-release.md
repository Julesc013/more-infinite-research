# MIR 3.2.5 Convergence Release

MIR 3.2.5 is the only planned public Factorio 2.1 release after 3.2.3. It combines C31's unreleased research-cost work with compatibility dispositions, proof-derived claims, exact environment identities, bounded support reporting, and the behavior-preserving internal consolidation needed to support them.

This document owns the 3.2.5 release contract. The [cross-release convergence programme](3.2.5-to-2.6-convergence-programme.md) owns sequencing, deferrals, the conditional 2.5.5 decision, and the 3.3/2.6 programme. The [ultimate convergence audit action register](ultimate-convergence-audit-action-register.md) owns the final audit corrections. `C32` remains a reserved monotonic floor until exact source or package identity is frozen.

Player-facing behavior is summarized in the [3.2.5 release notes](notes/release-notes-3.2.5.md) and [migration guide](3.2.5-migration-guide.md). The [development readiness record](3.2.5-development-readiness.md) maps every programme gate to implemented, development-proven, and still-open work without promoting development evidence into a release claim.

## Public contract

- Existing technology, setting, locale, runtime, and profile identifiers remain stable.
- New settings use neutral defaults.
- Default behavior remains equivalent to 3.2.3 except for named, evidence-backed compatibility corrections.
- Old profiles remain readable and unknown future fields remain preserved.
- The public upgrade path is 3.2.3 to 3.2.5.
- Breaking compiler and extension-platform changes remain 3.3 work.

## Execution slices and scope firewall

C32 is delivered as independently reviewable slices:

1. Complete and migrate the canonical cost contract from the closed C31 checkpoint.
2. Derive compatibility dispositions and explanations from existing compiler authorities.
3. Separate planned, applied, and realized lifecycle truth without granting reports mutation authority.
4. Bind proof assertions to exact environment identities and explicit claim dimensions.
5. Add bounded support, privacy, localization, and resource-safety surfaces.
6. Consolidate internals only where earlier slices earn the change and prove default-behavior parity.

The following remain outside 3.2.5: MEP-1, arbitrary external fragments, new parallel IRs, a general semantic-graph rewrite, ProcessIR, broad provider generalization, a runtime compiler, and a universal target-projection engine. Planning those capabilities does not move them into C32.

The release-value firewall is narrower than the whole convergence programme. Source freeze is blocked by complete cost behavior and transition proof; exact default, upgrade, configuration-change, and save/reload parity; terminal per-leaf dispositions; proposition and environment locks; bounded localized support and privacy behavior; exact package composition and manifest proof; a public-contract ABI diff; explicit Factorio 2.0 slice dispositions; trustworthy release-controller behavior; and the complete candidate qualification sequence.

Source freeze is not blocked by completing all PowerShell migration, deleting every target-line mirror, obtaining source locks for every museum installation, completing MEP-1, introducing typed `SettingSpec`, adding a runtime service registry, implementing `ProcessIR`, generalizing trusted external adapters, or producing the broad 3.3-to-2.6 generation platform. These are valuable follow-on changes, not reasons to keep a releasable 3.2.5 open.

A proposed 2.5.5 is a decision gate, not a promised release. It may proceed only if immutable 3.2.5 semantics can be projected with bounded Factorio-2.0 adapters, reconstructed deterministically, and qualified independently. If it requires duplicated canonical logic or a second compiler, no 2.5.5 candidate is created.

## Research costs

Every MIR-owned or explicitly supported native-owner research uses the canonical contract:

```text
cost(L) = (B + A * (L - S)) * G ^ (L - S)
```

The numeric parameters derive fixed, linear, exponential, and hybrid behavior. There is no redundant model selector. Unknown external formulas are preserved when no override is requested and reject an explicit override safely rather than being guessed.

The `INC-2026-0054` source repair now uses versioned old/new transition descriptors, `new_fraction = old_fraction * old_cost / new_cost`, the bounded canonical evaluator, fail-closed unknown handling, distinct semantic and authority digests, and the sixteen fixed, linear, exponential, and hybrid transitions. Candidate freeze remains blocked until exact default parity, continuous-versus-save/reload equivalence, bounded parser and numeric behavior, upgrade/configuration-change coverage, final Factorio 2.0 disposition, and candidate-bound regression proof close the proposition.

## Compatibility explanations

The release derives subject-level planned, applied, and realized dispositions from the existing catalog, compiler result, transformation plan, mutation journal, and final state. Reporting is a read model and has no mutation authority.

Machine reports use stable outcome and reason codes. Human reports are localized and answer what happened, why, which authority decided it, whether it is safe, which setting may change it, and which proof supports it.

## Proof and environments

Public compatibility text remains derived from the existing maturity, behavior, and scope taxonomy plus typed proof assertions. Exact environment locks bind the Factorio binary and data, complete mod closure and hashes, startup settings, load order, target adapters, and assertion definitions.

## Privacy and resource safety

Support exports omit personal identity by default, redact paths and tokens, use deterministic allowlisted content, and enforce encoded bytes, decoded bytes, depth, cardinality, selector, string, row, and report-size limits. MIR does not upload reports or require telemetry.

## Factorio 2.0 projection

Every product slice declares whether it is portable unchanged, portable with an adapter, omitted, replaced on the target, tooling-only, or unsupported. The immutable 3.2.5 semantics may be projected to 2.5.5 only after the feasibility gate, deterministic reconstruction, and independent Factorio 2.0 qualification. A real reporting adapter is required because the 2.0 target lacks mod-data transport.

## Release gates

The release requires exact 3.2.3 upgrade proof, cost-model realization and runtime-transition proof, disposition parity, compatibility environments, configuration recovery, privacy and localization review, paired performance, deterministic packaging, protected qualification, sealing, publication, and public-byte verification. No observation, performance result, attestation, or proof may bind to the reserved `C32` floor; candidate-bound work begins only after immutable identity exists.
