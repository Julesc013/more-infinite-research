# MIR 3.2.5 Convergence Release

MIR 3.2.5 is the only planned public Factorio 2.1 release after 3.2.3. It combines C31's unreleased research-cost work with the bounded research-cost compatibility disposition, typed proof, support record, and target adapter already admitted by `325-B0`. C31 remains permanently superseded-unpublished.

This document owns the 3.2.5 release contract. The [cross-release convergence programme](3.2.5-to-2.6-convergence-programme.md) owns sequencing, deferrals, the conditional 2.5.5 decision, and the 3.3/2.6 programme. The [ultimate convergence audit action register](ultimate-convergence-audit-action-register.md) owns the final audit corrections. `C32` remains a reserved monotonic floor until exact source or package identity is frozen.

Player-facing behavior is summarized in the [3.2.5 release notes](notes/release-notes-3.2.5.md) and [migration guide](3.2.5-migration-guide.md). The [development readiness record](3.2.5-development-readiness.md) maps every programme gate to implemented, development-proven, and still-open work without promoting development evidence into a release claim.

## Public contract

- Existing technology, setting, locale, runtime, and profile identifiers remain stable.
- New settings use neutral defaults.
- Default behavior remains equivalent to 3.2.3 except for named, evidence-backed compatibility corrections.
- Old profiles remain readable and unknown future fields remain preserved.
- The public upgrade path is 3.2.3 to 3.2.5.
- Breaking compiler and extension-platform changes remain 3.3 work.

## Narrowed execution scope and firewall

The 2026-08-05 maintainer decision limits the release to independently reviewable slices that are necessary for the unified research-cost product:

1. Complete and migrate the canonical cost contract from the closed C31 checkpoint.
2. Preserve exact 3.2.3 defaults, direct upgrades, progress, coefficient anchoring, precision, profiles, settings, owners, and current compatibility corrections.
3. Ship the admitted bounded B0 research-cost disposition, typed proof assertion, privacy-safe support record, and Factorio 2.0 adapter disposition.
4. Bind only the release-specific environments, privacy, localization, performance, manual, protected, seal, publication, and public-byte proof needed for the exact frozen package.

The following remain outside 3.2.5: generalized all-stream/per-leaf dispositions; general-purpose public ProofAssertion and EcosystemProfile authorities; a universal support bundle and broad remediation catalog; a broad all-change Factorio 2.0 projection inventory; optional consolidation; MEP-1; arbitrary external fragments; new parallel IRs; a general semantic-graph rewrite; ProcessIR; broad provider generalization; a runtime compiler; and a universal target-projection engine. Planning those capabilities does not move them into C32.

The release-value firewall is narrower than the whole convergence programme. Source freeze is blocked by essential B1 cost behavior and transition proof; exact default, upgrade, configuration-change, save/reload, second-reload, ownership, parser, numeric, and realization parity; release-specific proposition and environment locks; bounded B0 support, privacy, and localization proof; exact package composition and manifest proof; a public-contract ABI diff; explicit Factorio 2.0 dispositions for shipped features; trustworthy release-controller behavior; and the complete candidate qualification sequence.

Source freeze is not blocked by completing all PowerShell migration, deleting every target-line mirror, obtaining source locks for every museum installation, completing MEP-1, introducing typed `SettingSpec`, adding a runtime service registry, implementing `ProcessIR`, generalizing trusted external adapters, or producing the broad 3.3-to-2.6 generation platform. These are valuable follow-on changes, not reasons to keep a releasable 3.2.5 open.

A proposed 2.5.5 is a decision gate, not a promised release. It may proceed only if immutable 3.2.5 semantics can be projected with bounded Factorio-2.0 adapters, reconstructed deterministically, and qualified independently. If it requires duplicated canonical logic or a second compiler, no 2.5.5 candidate is created.

## Research costs

Every MIR-owned or explicitly supported native-owner research uses the canonical contract:

```text
cost(L) = (B + A * (L - S)) * G ^ (L - S)
```

The numeric parameters derive fixed, linear, exponential, and hybrid behavior. There is no redundant model selector. Unknown external formulas are preserved when no override is requested and reject an explicit override safely rather than being guessed.

The `INC-2026-0054` source repair now uses versioned old/new transition descriptors, verifies Factorio's `new_fraction = old_fraction * old_cost / new_cost` normalization without applying it twice, retains the bounded canonical evaluator and fail-closed unknown handling, separates semantic and authority digests, and covers the sixteen fixed, linear, exponential, and hybrid transitions. Candidate freeze remains blocked until exact default parity, continuous-versus-save/reload equivalence, bounded parser and numeric behavior, upgrade/configuration-change coverage, final Factorio 2.0 disposition, and candidate-bound regression proof close the proposition.

## Bounded compatibility explanation

The release derives the bounded research-cost proposition's planned, applied, and realized disposition from the existing catalog, compiler result, transformation plan, mutation journal, and final state. Reporting is a read model and has no mutation authority. Generalized all-stream disposition productization is deferred.

The bounded machine record uses stable outcome and reason codes. Release-specific human documentation explains the shipped behavior and its safe settings. A universal localized support product is deferred.

## Proof and environments

The shipped B0 typed assertion and essential B1 propositions bind release-specific environment locks for Base, Space Age, upgrades, configuration changes, and the governed ecosystem matrix. General-purpose proof/environment public product authorities are deferred.

## Privacy and resource safety

The bounded B0 support record omits personal identity, uses deterministic allowlisted content, and enforces its published budgets. Release-specific privacy, localization, truncation, diagnostics-off, and manual review remain mandatory. MIR does not upload reports or require telemetry. A universal support-bundle product is deferred.

## Factorio 2.0 projection

Every feature actually shipped by 3.2.5 declares whether it is portable unchanged, portable with an adapter, omitted, replaced on the target, tooling-only, or unsupported. A broad projection inventory is deferred. No 2.5.5 authority exists; one may be considered only after public 3.2.5 and a formal feasibility gate. The shipped B0 record retains its validation-log adapter disposition because Factorio 2.0 lacks mod-data transport.

## Release gates

The release requires exact 3.2.3 upgrade proof, cost-model realization and runtime-transition proof, bounded B0 disposition integrity, release-specific compatibility environments, configuration recovery, privacy and localization review, paired performance, deterministic packaging, protected qualification, sealing, publication, and public-byte verification. No observation, performance result, attestation, or proof may bind to the reserved `C32` floor; candidate-bound work begins only after immutable identity exists. A package-visible defect after assignment requires a later candidate and may move the release date.
