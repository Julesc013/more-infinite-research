## Cost-transition defect discovery

The earlier `space-age-native-owner-settings-config-change` scenario reported a pass after observing `0.10885649918078` at realized old cost `7593` and then applying a second conversion to `0.028213660509272` at realized new cost `29296`. The fixture had initialized progress to `0.42`; Factorio had already produced the correct completed-work value `0.42 * 7593 / 29296 = 0.10885649918078` before MIR's configuration handler. The old assertion checked only the second conversion's internal arithmetic, so it certified lost work.

The new direct 3.2.3-to-3.2.5 upgrade matrix independently exposed the same defect. Its Space Age native-owner row stored `0.42` at realized source cost `17521`; Factorio normalized that to `0.71403260236755` for the 3.2.5 realized cost `10306`, then MIR incorrectly reduced it again to `0.52606729572839`. These failed runs are retained as fault evidence. The repair leaves Factorio-normalized progress untouched and strengthens both fixtures to compare original completed units with the final engine count. All sixteen fixed, linear, exponential, and hybrid descriptor calculations plus tampered-digest and over-budget refusal remain analytical coverage; fresh runtime closure is required before a new development package can become playtest-green.

The next exact upgrade run passed the repaired native-owner row and then exposed a separate base-continuation migration defect. MIR 3.2.3 treated `mir-cost-base-inserter-capacity-bonus = 200` as the level-one coefficient in `200 * 3.33333 ^ (L - 1)`, producing a realized level-8 cost of `914488`. The unified 3.2.5 planner incorrectly copied `200` into the level-8 anchor cost. `INC-2026-0057` records the repair: retain the stable setting ABI, project the coefficient onto the first controlled level, and begin any new additive increment from that projected anchor. The complete five-archetype upgrade matrix remains required before these working bytes may become playtest-green.

The first projection build then produced `914494`, proving that projection alone was insufficient: the 3.2.3 emitter serialized formula operands at six significant digits, while the new model used the raw `3.333333333333` setting value. The complete repair preserves the old `3.33333` realized operand before anchor projection. Both failed development packages and their exact Factorio roots remain fault evidence.

Exact development plan material `169A1C467E8E85B878B174D36774A61D08BF3DAB934C9E5AF047F6F6DC6534D7` bound the completed repair to archive `E176263EC5AF411D1C77EFBEC959120BA9C22C10D06A53E6B49B09E2B2E276E3`. All five direct upgrade archetypes passed: Base default, Space Age native owner, automatic family creation, base continuations, and removed-mod configuration change. The continuation row retained realized cost `914488`, selected research, level, fractional progress, and completed work. The independent Space Age settings-change row also passed with Factorio-normalized progress `0.10885649918078` at cost `29296`, no second conversion, all sixteen analytical descriptor transitions, and no force-wide reset. This is local development proof, not candidate or protected release qualification.

This proof is useful development evidence, but it is not candidate-bound or protected release evidence. The source and package must be rebuilt and the scenario rerun after every package-visible change.
