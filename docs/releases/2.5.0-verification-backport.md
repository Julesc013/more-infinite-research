# MIR 2.5.0 Verification Backport Contract

The Factorio 2.0 branch is reconstructed from MIR 2.4.9 commit `7ebe93029695bbf809a15a14c6540530738a9e62`, descends from published tag `3.2.0`, projects portable C20 package source `303de261629149af5f50bd210368e61423f1a299`, and freezes the current package at `4a19c26c5abf479cbe4cf48f477eec6e3ab2474d`. The provisional archive SHA-256 is `546F82FB58288F492F7B3D21AF4F597B21D4477B18FF9D98A18BE0E5E2D26580`.

Every target fingerprint is independent: package, Factorio binary, target profile, fixtures, dependency closure, scenario, approved delta, upgrades, performance, manual review, protected qualification, and seal. Factorio 2.1 evidence is useful design input but never substitutes for Factorio 2.0 evidence.

The automated gate requires static validation, deterministic packaging, exact Base and supported DLC loads, the complete Factorio 2.0 scenario catalog, approved delta against 2.4.9, mandatory 2.4.9 upgrade, optional 2.4.5 upgrade, paired performance against 2.4.9, exact available ecosystems, and aggregate evaluation with no evidence reuse. The expected pre-playtest state is all machine-verifiable tests passed with the manual row incomplete.

After gameplay tuning freezes the final bytes, rerun the entire no-reuse campaign, complete the exact manual attestation, dispatch protected qualification, independently check the seal, promote to `legacy`, tag, publish the already-sealed ZIP, and verify downloaded hashes. No earlier step may claim release qualification.
