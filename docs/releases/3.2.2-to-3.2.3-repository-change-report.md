## Player-visible 3.2.3 changes

### Platform Productivity

- Removed `ice-platform` and `space-platform-foundation` from Landfill Productivity ownership.
- Added a stable `research_platform` generated stream and technology identity.
- Applied `+10%` productivity per level to `ice-platform`.
- Applied `+5%` productivity per level to `space-platform-foundation`.
- Reused Landfill Productivity progression rules while additionally requiring `cryogenic-science-pack`.
- Added the new Platform setting, locale key, stream manifest row, stable generated ID, and catalog assertions.
- Added `cryogenic-science-pack` to Ice Productivity so Aquilo-specific ice bonuses cannot be researched from Nauvis progression alone.

### Structural logistics productivity

- Added entity-aware structural recipe discovery for transport belts, underground belts, splitters, lane splitters, loaders, and inserters.
- Added a conservative `+0.5%` Belt Productivity fallback for structurally discovered modded logistics recipes.
- Added a conservative `+1%` inserter fallback for structurally discovered modded inserters.
- Preserved reviewed family precedence: explicitly reviewed logistics families replace fallback ownership instead of receiving duplicate or weaker effects.
- Preserved recipe-level productivity denials, including returned cryogenic-fluid outputs marked as productivity ignored.
- Added blanket discovery that does not depend on a third-party mod's recipe names or tier names.

### Advanced Belts coverage

- Added an exact compatibility claim and support lane for `AdvancedBeltsSA`.
- Added assertion fixtures covering the three post-Turbo belt tiers, underground belts, and splitters.
- Added a governed test-only Factorio-line adapter that changes only the third-party archive's declared Factorio version and proves all other payload bytes unchanged.
- Verified all expected MIR productivity effects and returned-fluid denial contracts during Factorio 2.1 data-stage execution.
- Recorded the upstream limitation honestly: the current AdvancedBeltsSA archive targets Factorio 2.0 and later fails Factorio 2.1 recipe-schema validation for its own `category`/`additional_categories` fields. Exact 2.0 and 1.1 binary qualification remains target-line work.

### Metadata and presentation

- Advanced `info.json` and the changelog to 3.2.3.
- Added player release notes and the exact immutable candidate identity block.
- Updated all 50 shipped locale files and 49 translation-memory authorities for Platform Productivity.
- Retained the 3.2.2 stable identities and added one new stable generated stream identity.

## Control Plane v5 implementation

### Typed authority

- Added typed change, incident, task, release, release-transition, and current-role records.
- Added strict JSON Schema 2020-12 definitions for observations, assertions, evaluations, contexts, evidence, revocations, TaskNodes, and release records.
- Added independent control-plane ABIs and the rule that AI cannot omit required proof.
- Added exact package locks for C24, P9, and active C26 while preserving immutable historical package identities.
- Generated current-candidate, dashboard, branch-status, publication, backport, TODO, and legacy release-ledger views from typed records.

### Semantic planning and optimized execution

- Added content-addressed semantic ownership and downstream domain graphs.
- Added a 44-node release graph: 42 executable TaskNodes and two result-only aggregates.
- Added content-eternal, candidate-bound, transition-bound, and protected-release-fresh freshness classes.
- Added exact effective-input manifests and conservative unknown-ownership handling.
- Added mutation calibration with nine cases and a zero false-negative budget.
- Added explicit archive ownership so a frozen `dist/*.zip` selects package and release obligations without causing an unknown-governance failure.
- Added an execution registry generated from scenario declarations and PowerShell AST identities.

### Observation, evidence, and contexts

- Separated native observation capture from pure assertion evaluation.
- Added immutable verification contexts with exact source, package, target, environment, registry, and task-plan locks.
- Added a content-addressed evidence store with indexes, leases, revocation, quarantine, and trust classes.
- Added aggregate evaluation that consumes admitted evidence rather than mutable workflow status.
- Added resumable execution and candidate staging for exact ZIP-based work.

### Release controller

- Added commands for validation, planning, registry generation, historical replay, context creation, evidence indexing, aggregation, calibration, qualification, release admission, backport admission, sealing, and promotion.
- Added protected workflow wiring in `.github/workflows/control-plane-v5.yml`.
- Added release nodes for approved delta, upgrade, ecosystem, performance, manual acceptance, protected qualification, seal, promotion, tag, publication, and public-byte verification.
- Added pre-qualification-aware release checks so `package-built` candidates remain valid without being misrepresented as qualified.

### Shadow equivalence and calibration

- Generated structural shadow analysis for C24 and P9 with no pending comparison dimensions.
- Mapped 113 C24 exact environments and the P9 target environments to v5 identities.

- Canonicalized performance-probe staging and bounded Windows paths for context-addressed Factorio artifacts.
