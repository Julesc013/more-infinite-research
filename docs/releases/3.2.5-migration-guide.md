# MIR 3.2.5 Migration Guide

The supported public upgrade is MIR 3.2.3 to MIR 3.2.5 on Factorio 2.1. Keep a normal save backup before testing a development package or changing startup settings.

## Before loading

Review any non-default base-cost or growth settings and the new per-level increment settings. An increment of zero preserves the previous fixed or exponential curve. A nonzero increment produces a linear curve when growth is one and a hybrid curve when growth is greater than one.

Existing `mir-cost-base-<technology>` values for finite-chain continuations keep their 3.2.3 meaning as a level-one formula coefficient. MIR retains the historical six-significant-digit formula behavior and projects that saved coefficient to the first new continuation level before applying the new additive increment. Do not manually replace those saved values with the displayed first-level research cost.

Do not install the unpublished MIR 3.2.4 development archive as an intermediate. Its C31 archive is retained only as immutable development evidence and is not part of the public upgrade contract.

## Native-owner research

At default settings MIR preserves a recognized native or modded research formula. When an explicit supported override changes its cost during configuration change, Factorio normalizes the active fraction to preserve completed unit-equivalent work. MIR retains that normalized value and does not convert it again.

If MIR cannot validate both the old and new versioned cost descriptors, it leaves fractional progress unchanged and records a refusal diagnostic. It does not reset force-wide technology effects, change the selected research, reorder the queue, or guess an external formula.

The same no-reset boundary applies when the configured productivity-family adoption signature changes. MIR updates its stored binding and performs only a recognized current-research cost conversion; it does not globally reapply technology effects or unrelated recipe state.

## Profiles and identifiers

Existing setting IDs, generated technology IDs, stream IDs, locale keys, runtime namespaces, and profile encoding remain stable. Existing profiles stay readable, missing new increment values use neutral defaults, and unknown future fields survive a decode/encode round trip.

## After loading

For an important save, verify the selected research, current level, fractional progress, queue order, completed technologies, and the research cost displayed for any native-owner technology whose cost controls changed. Save, reload, and confirm the same state before continuing long-term play.

Report unexpected behavior with the exact MIR archive hash, Factorio version, enabled mod archives, startup settings, source save, and relevant log. Remove usernames, absolute paths, tokens, and unrelated save data before sharing a report.

## Factorio 2.0

Do not copy the 3.2.5 package to a Factorio 2.0 installation. A possible MIR 2.5.5 will be generated only after 3.2.5 is immutable and the separate Factorio 2.0 feasibility and qualification gates pass.
