# ADR 0007: MIR 4.1 Foundation Completion Boundary

## Decision

MIR 4.1 completes the physical and executable foundation established by the post-4.0 governance work. Its completion boundary includes truthful current records, one canonical package source, deterministic common-source plus target-overlay materialization, four independently proved target products, generated repository and package documentation, one supported command surface, one release engine, one executable test authority, release-critical bridge retirement, and bounded behavior-preserving decomposition needed to remove current mutable ambiguity.

The fixed point is measured as:

```text
zero ambiguity
zero duplicate writer
zero uncontrolled bridge
zero unexplained package difference
zero stale current authority
zero release-critical transitional dependency
```

Historical compatibility material does not need to be deleted merely because it is old. A retained bridge must be read-only, package-excluded, unused for current product semantics, owned, tested, bounded, and recorded in the bridge-expiry ledger.

## Ordering

Package equivalence is the gate, not directory neatness. The source cutover proceeds from exact four-target 4.0 baselines through deterministic common/overlay classification and shadow materialization, proves F210 and F200 parity, proves F110 and F100 independently, establishes `src/mod/` as the writable source, rehearses rollback, and only then retires the former writer.

Implementation decomposition begins only after package parity and the package-authority cutover. A split must preserve semantic outputs, plans, journals, package trees, target results, upgrade behavior, negative behavior, and acceptable performance. Work that cannot be reviewed and proved safely remains unchanged and receives an explicit disposition.

## Later releases

MIR 4.2 begins integration-kernel and built-in ecosystem admissions. MIR 4.3 industrializes selection, evidence lifecycle, recovery, measured release lanes, offline operation, and preservation. MIR 4.4 and later remain unallocated until evidence supports a coherent external outcome.

This decision allocates no source or distribution version and grants no tagging, signing, sealing, publication, or support authority. `main` remains the latest stable line, `dev` remains the next-minor-or-major integration line, and `release/4.0` remains the protected 4.0.x maintenance line.
