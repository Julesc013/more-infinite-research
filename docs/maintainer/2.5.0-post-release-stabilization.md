# MIR 2.5.0 Post-Release Stabilization

## Objective

Run a 24-hour stabilization campaign against the immutable MIR 2.5.0/P11 public package. Discover and classify credible defects before major 3.3/2.6 work begins, then either freeze 2.5.0 as the qualified Factorio 2.0 baseline or release one consolidated 2.5.1 hotfix.

The campaign does not authorize package changes. P12 is created only after a player-package defect is reproduced against the exact public bytes.

## Concurrency rule

Protected retry `30740083663` owns the Factorio/performance lane while it can still schedule Factorio work. Adopt and monitor that worker. Do not start a duplicate protected run, paired performance campaign, or other heavy Factorio workload on the same host.

Static analysis, governance reconciliation, plan materialization, artifact inspection, and offline evaluation may proceed when they do not perturb the protected lane.

## Execution order

1. Prove immutable repository and public-byte identity, including independent install/save/reload of each available public copy.
2. Complete direct 2.4.9 to 2.5.0 transition and persistent-state tests; keep 2.4.5 and 2.4.0 as secondary evidence.
3. Exercise the changed Platform, Ice, structural-logistics, planet/location, and Py-finalizer surfaces.
4. Run a pairwise settings covering array plus the explicitly required high-risk triples.
5. Run exact ecosystem lanes with separate LOADS, INTEGRITY, SEMANTIC, PROGRESSION, UPGRADE, and INTERACTIVE verdicts.
6. Run negative, fuzz, and mutation campaigns; require zero impact false negatives.
7. After the protected lane is idle, run governed performance, memory, and soak work without changing official budgets.
8. Triage every observation and freeze the defect list before any package edit.

## Transition invariants

Direct 2.4.9 to 2.5.0 testing must cover Base, Space Age, current and fractional infinite research, completed levels, automatic attachment/generation modes, owner state, productivity caps, unrestricted modules, mod add/remove, and configuration-change settings.

Require retained research, fractional progress, settings and storage; one effective owner; no stale or duplicate effects; successful reload; idempotent second reload; and continuous-versus-reload state equivalence.

## Changed-surface invariants

Platform and Ice coverage includes enabled/disabled combinations, existing levels, current/queued research, cryogenic availability, lab reachability, and researched state. Require separate Platform progression, no Landfill-level transfer, cryogenic gating, exact +10% ice-platform and +5% space-platform-foundation effects, and one owner per recipe.

Structural logistics coverage includes opaque names, loaders, lane splitters, hidden and denied recipes, zero caps, recycling, catalyst/self-return, ignored coolant, missing and unrelated `place_result`, reviewed/fallback overlap, multiple producers, and multi-entity recipes. Membership and ownership must be deterministic.

Planet/location coverage includes valid and missing planet/space-location targets, mod add/remove, unrelated locations, and absence of Factorio 2.1-only recovery behavior. Py coverage uses the exact locked 2.0 closure, reordered enumeration, postprocessor ordering, `casting-gear` sanitation, sibling retention, exact prune accounting, and reload.

## Settings coverage

Generate a pairwise covering array over automatic action, new-research creation, reviewed-data requirement, unrestricted modules, productivity-cap mode, global scaling, per-technology scalar, and Platform/Ice/Landfill enablement.

Always run these triples:

```text
apply + create-new + reviewed-only=false
disabled + create-new=true + reviewed-only=false
unrestricted-modules + high-cap + self-recycling-only
preview + mod removal + save reload
apply + AdvancedBeltsSA + Py
```

Disabled overrides subordinate settings; preview never mutates; user preference never overrides hard safety; settings round-trip unknown values; Factorio 2.1-only settings remain absent or inert.

## Observation and evidence model

Materialize the verification plan before execution. Group work by the exact environment signature: Factorio binary, candidate ZIP, official modules, third-party closure, startup settings, fixture bundle, process model, and observation ABI.

Capture one canonical observation per compatible signature, then evaluate separately addressable assertions offline. Reuse only exact trusted fingerprints with recorded reasons. Adopt matching in-progress work. Rerun failed tasks and invalidated prerequisites, and retain revoked/corrupt evidence rather than rewriting it. Run one independent no-reuse qualification only after a package candidate is frozen.

## Finding disposition

- Player startup, prototype, upgrade/state, ownership, settings, progression, ecosystem, target-adapter, or serious package-code performance defects can create 2.5.1.
- Network/upload failures, verifier/parser defects with sound observations, stale governance, and missing protected evidence are tooling or authority work and do not create 2.5.1.
- Cosmetic preferences, speculative balance, new features, and broad generation wait for 2.6/3.3.
- Target-neutral defects are fixed canonically on `dev` and projected to the target line.
- Factorio-2.0-only defects become explicit target adapter repairs with a 2.6 disposition.

## Decision cut

At the end of discovery on Monday, 3 August 2026:

- If no package defect is reproduced, record post-publication qualification, preserve the exact environment/capability/adapter/omission/upgrade/ecosystem/performance/manual/publication bundle, and freeze 2.5.0 as the 2.6 baseline.
- If one or more package defects are reproduced, freeze one defect list and create P12 from `legacy`. Require deterministic packaging twice, exact 2.5.0 to 2.5.1 upgrade/reload, secondary 2.4.9 upgrade evidence, approved delta, affected settings/ecosystems, paired performance, differential manual review, protected qualification, independent seal verification, fast-forward-only legacy promotion, annotated tag, and public re-download verification.

Never release an empty 2.5.1 merely because additional assurance completed.
