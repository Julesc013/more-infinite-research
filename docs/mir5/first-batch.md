# First implementation batch — bounded assignment

This is a proposed assignment to the local coding session, not an activated background job or release authorization.

## Outcome

Demonstrate one actual existing MIR research through a direct Generator path, and prepare the same-output comparison before mass porting. Recover the difficult continuation/cap contracts now so the simple slice cannot be mistaken for architecture-wide proof.

1. Reconcile current branch/dirty work and active jobs. Pin the released baseline, not just its version. Keep main/public objects unchanged.
2. Adopt `spec/mir5/` by review. Use new player source `source/mir5/`, explicitly selected by the package/test command. Do not import old `source/prototypes/mir` modules. Do not create `mod/` as a second authority.
3. Recover `research_gears`' actual resolved technology ID, settings/default/import precedence, effects, prerequisites, science, formula/time and cap behavior. Source keys alone are not complete definitions.
4. Recover the existing K2/K2SO finite 1–3/continuation/native-crystal/carrier requirements and worker-speed cap/runtime/Library state expectations. Their implementation is a subsequent bounded task, not permission to expand this slice.
5. Implement the recovered gear research with ordinary native tables and a small reusable constructor only where needed. Keep settings-stage imports small. No generic IR, planner, digest chain, global discovery or fallback.
6. Host-check the independent expected result and mutation/missing-reference opponents. In an available pinned native environment, check actual research effect, one relevant changed setting, saved disposable world and two reloads. If unavailable, report the precise missing input and mark native results not run.
7. Prepare a private direct replay for one existing large profile, preserving the actual full output/patches. Compare published 4.7, replay and no-MIR where valid using the existing verified responsive-menu endpoint. Do not use the partial slice as a complete performance contender.
8. Stop. Return changed files, code/import footprint, commands/results, remaining parity/migration gaps and the next bounded task.

Do not load a production full MIR save with the incomplete slice. Do not invent native runner flags. Do not start all API methods, another SDK framework, a GUI redesign, AIDE integration or all historical ports in this batch. All delivered target/features remain stable-release obligations.

After the slice works, exercise a second effect and two independent API consumers, then difficult progression/state behavior before broad extraction. The API shape remains a candidate until those consumers validate it.
