# Architecture and regression response

## Whole-project reassessment — 20 November 2026

The maintainer has explicitly widened this reassessment to the whole project and paused the recurring development cycle. Restricting the response to worker storage was insufficient. This section assesses source construction, settings, compatibility, version composition, runtime and migrations, presentation, test design, development tooling, evidence and release decisions at commit `0bb697f512c85ebd8d40fc93b3e6d0ed979a49f5`. It extends the existing findings below rather than introducing another issue ledger or specification. The later sections retain their original evidence and narrower checkpoints; their earlier source stamps are not the scope of this new assessment.

The assessment used a tracked-file inventory, literal dependency scan, focused source inspection, the existing architecture audit, current progress records and two bounded read-only reviews with separate construction and runtime responsibilities. It did not inspect every line, execute gameplay, run a host suite, establish whole-product performance, or prove the absence of other bugs. Confirmed conditional code paths are distinguished from observed player failures. This is an architecture assessment across the product, not an exhaustive correctness certificate.

### Decision

MIR has recurring defects in the meaning and ownership of state across module boundaries, duplicated authorities for family and compatibility facts, and a verification process that can spend substantial effort on its own apparatus without closing the player operation. These are broader than worker storage. Substantial restructuring is warranted across the affected boundaries. The reviewed evidence does not justify deleting the entire codebase: several existing components already implement the intended simpler architecture. Keep, refactor or replace each component against observable criteria; do not commit to preserving every subsystem merely because it was rewritten recently.

The hourly MIR continuation was disabled on 20 November at 08:20:38 UTC. That changes the scheduled task, not independently running machines, other conversations or external services. This reassessment does not authorize a release, claim a repair, change player bytes or reactivate unattended work.

### New and expanded findings

**F11 — Failed force observation can delete restoration rights outside worker storage. Confirmed conditional fault path; gameplay trigger not reproduced.** In [competing_productivity.lua](../../source/runtime/competing_productivity.lua), `force_for_index` catches any `game.forces[index]` exception and returns nil. `discard_unselected_rights` treats that result as an absent/invalid force and deletes `owned_disabled[index]`. The code can discard MIR's record of responsibility for disabled research without establishing that the force disappeared. This is the same semantic distinction already repaired in cap admission; the old report listed this consumer as a follow-up. Observe and validate the live-force set before cleanup, retain unexpected causes, and test that failed observation preserves rights. Do not change valid missing-force cleanup into a permanent leak.

**F12 — A production fallback accommodates an unrealistic host reload. Confirmed design defect; current gameplay consequence unmeasured.** [scripted_effects.lua](../../source/runtime/scripted_effects.lua), `resolved_config`, returns disabled/zero configuration when its input is not a table. Its comment explicitly justifies this for a host reload reusing a base-only settings module, while bootstrap activates scripted effects on the Space Age route. Missing required effective configuration is therefore indistinguishable from an intentionally disabled feature and can flow into contribution reconciliation. Correct the test world's parse/activation lifecycle; represent genuinely absent capabilities at composition, and validate required configuration when the component is active. A forgiving public query and an internal mutation prerequisite have different failure policies.

**F13 — Library renders failed queue observation as an empty queue. Confirmed presentation fault path; no queue mutation shown.** [library.lua](../../source/runtime/library.lua), `queue_entries`, returns an empty table after a failed queue read or failed iteration. `update_queue_content` then shows its empty-queue message. [library_model.lua](../../source/presentation/library_model.lua), `cap_fact`, already distinguishes an unavailable observation. Apply that distinction to queue presentation: carry available/unavailable plus bounded cause separately from rows. Graceful UI failure must remain non-destructive and must not make the underlying queue look empty.

**F14 — Package minimum-version metadata gates gameplay integration selection. Confirmed coupling; future regression risk.** Five selectors compare `target.minimum_base` with an exact captured floor: [Bob/Angel F200](../../source/compatibility/bob_angel_f200_combined_profile.lua), [Bob/Angel F210](../../source/compatibility/bob_angel_f210_profile.lua), [Bob Plates](../../source/compatibility/bob_plates_profile.lua), [Bob productivity](../../source/compatibility/bob_productivity.lua) and [ATAN](../../source/compatibility/atan_profile.lua). [platform/target.lua](../../source/platform/target.lua) identifies this value as package metadata; it is not the observed running engine or a semantic capability. A floor-only metadata change can suppress selection or throw before raw-contract validation. Identify the concrete capability each gate protects, preserve real engine restrictions, and separate qualification tuples from applicability. Do not simply delete these checks without reviewing those contracts. This is not evidence that a current reporter has hit a floor-change regression.

**F15 — Ordinary recipe-row validation has duplicated and diverged. Confirmed policy/representation inconsistency; affected gameplay not reproduced.** The shared [ordinary_rows.lua](../../source/compatibility/ordinary_rows.lua) is used by material routes and BobTech, but [bob_angel_materials.lua](../../source/compatibility/bob_angel_materials.lua) keeps a near-copy and [material_catalogue.lua](../../source/compatibility/material_catalogue.lua) keeps a divergent K2SO copy. Shared/Bob-Angel accept named and positional name/amount fields and reject nonzero catalysts. The K2SO copy accepts named fields only and lacks the catalyst check. Some field differences can be target-specific; document them instead of assuming equivalence. Reuse one small semantic row validator with explicit target policies while keeping ownership, recipe economics and admitted variants local to adapters.

**F16 — Family facts have multiple apparent authorities. Confirmed maintenance risk; no new mismatch reproduced.** Advanced-circuit tuning, for example, appears in both [base.lua](../../source/compatibility/modern_catalogue/base.lua) and [historical_settings.lua](../../source/research/historical_settings.lua). [settings.lua](../../source/research/settings.lua) takes effective defaults from the latter and applies profile visibility. The ordinary renderer in [modern.lua](../../source/research/modern.lua) uses resolved settings for most values, retaining `definition.tuning` for the research-time-zero sentinel. Construction and runtime catalogue selection also take different paths. Establish one owner per current fact, remove misleading unused duplicates, and project those facts into each lifecycle phase. Preserve deliberate frozen historical expectations. The shared K2 material stage identities and material renderer show an existing direction; another catalogue language is unnecessary.

**F17 — Lifecycle composition has inconsistent validation-before-write boundaries. Confirmed structural risk; no assertion of persisted corruption after a fatal load.** [bootstrap.lua](../../source/runtime/bootstrap.lua) preflights several owners, applies worker transitions, then invokes Imersite, competing-productivity and scripted-effect reconciliation. Imersite has its own local preflight/checkpoint restoration, so it would be inaccurate to describe every later consumer as unvalidated. Competing reconciliation interleaves reads and writes per force; agriculture refresh precedes spoilage reconciliation. Initialization and force events compose these operations differently again. Specify required observations before dependent writes, with one application owner for each contribution. Preserve local rollback where it is effective. Do not promise a universal transaction across arbitrary engine setters/callbacks.

**F18 — Test and development machinery have become a substantial second maintenance surface. Confirmed footprint/coupling observations; no measured token or runtime attribution.** A Python AST scan of top-level `tests/test_*.py` found 34 files importing sibling test modules and 19 assigning attributes on imported sibling-module aliases. These counts do not prove order-dependent failures; process isolation limits some leakage. They do establish implicit setup dependencies. The worker world also copies the canonical technology into its counterpart, which is suitable for downstream accounting tests but cannot independently validate final data-stage coherence. [validate.yml](../../.github/workflows/validate.yml) has 80 literal exact-commit fetch statements across its jobs, and ordinary PRs invoke [the full host driver](../../tests/Test-MIR5HostControls.ps1); the count is not 80 downloads on every run. The driver exposes plan/runtime arguments but no focused selection. Consolidate exact historical-input declarations and shared builders where semantics match, retain their immutable references, and add impact selection before changing any required merge gate. Do not delete adverse receipts or weaken gameplay acceptance to reduce the estate.

**F09 expanded — Responsibility concentration is broader than worker storage.** Physical line counts at this commit are Library 3,324; worker storage 1,961; native credits 1,366; lifecycle 1,168; bootstrap 872; modern compatibility catalogue 1,412; historical settings 1,453. Declarations are not inherently bad because they are long. The concern is control flow mixing profile selection, historical interpretation, accounting, observation, mutation and presentation. Extract around owned state and explicit inputs/outputs, not arbitrary line limits. Mechanical file moves must remain separate from behavior changes.

**Current startup blocker remains separate.** The supplied published17 `canonical4/full default4 contract or custody differs` report occurs in current prototype-pair validation before historical `default_origin` admission. At the audited head, the same grouped rejection remains, and `matches_default_owner` still collapses detailed assertion failures to a boolean. The exact failed predicate and reporter's final definitions remain unknown. Historical-admission corrections and improved diagnostics do not establish its functional repair. The recurring weakness is inconsistent contract definition and failure classification across production, observation and migration boundaries; this is not proof that every report shares one bad field or that adding more guards would repair it.

## Conditions for replacing a component

Replace an individual component if its required state cannot be expressed with unambiguous meanings, mutation cannot have one coherent owner, correct changes repeatedly require unrelated infrastructure edits after a reasonable responsibility split, or measured behavior exposes an inherent algorithmic limitation. Any replacement needs explicit old-save compatibility and independent acceptance before use.

None of those conditions has been established for MIR 5 as a whole. The practical decision is substantial targeted correction and component refactoring, with actual preservation outcomes and lifecycle sequences controlling release claims. No finite test set can guarantee arbitrary future mods never alter prototypes; supported updates should nevertheless preserve progress without player resets, and the demonstrated failure classes should have enforced regression opponents across their real consumers.
