# More Infinite Research

[![MIR](https://github.com/Forkatron/more-infinite-research/actions/workflows/mir.yml/badge.svg?branch=main)](https://github.com/Forkatron/more-infinite-research/actions/workflows/mir.yml)

More Infinite Research (MIR) extends Factorio with configurable, compatibility-aware infinite research. MIR discovers eligible technologies and production families, builds stable research streams, preserves save progression across upgrades, and explains every admitted, preserved, omitted, or rejected result.

The latest published product remains **MIR 4.0.0** until the signed `v4.1.0` tag and release exist. MIR 4.1.0 is the four-target repository and package fixed point; when `main` contains this source before publication it is the exact sealed, unpublished candidate awaiting the final maintainer playtest. Repository source archives are not player packages.

## Choose the right target

Each target is generated independently from the canonical `src/mod` source and its target overlay. Use the release ZIP matching your Factorio line.

| Target | Factorio line | MIR 4.1 distribution | Technical / publication role |
| --- | --- | --- | --- |
| F210 | 2.1 experimental | `4.1.21000` | required / primary |
| F200 | 2.0 | `4.1.20000` | required / primary |
| F110 | 1.1 | `4.1.11000` | required / supplemental LTS |
| F100 | 1.0 | `4.1.10000` | required / supplemental LTS |

F210 follows the latest installed official Factorio 2.1 experimental build until the first official 2.1 stable release exists. Every qualification still records one exact executable, runtime API, prototype API, and changelog identity. When that identity changes, MIR opens fresh API, compatibility, implementation, functionality, fixture, performance, documentation, and stable-transition review work before reusing any claim.

F200, F110, and F100 use fixed exact engine profiles. Evidence from one target never substitutes for another.

## What MIR provides

- **Configurable infinite research.** Choose fixed, linear, exponential, or hybrid cost curves, research time, effects, and optional maximum levels.
- **Stable identities and upgrades.** Manifest-backed stream IDs, migrations, configuration reconciliation, and runtime-state checks preserve researched levels, fractional progress, queues, and settings.
- **Target-aware generation.** One semantic source produces four self-contained packages with explicit overlays, replacements, omissions, locale, and migration boundaries.
- **Compatibility safety.** MIR observes existing owners and late prototype state, avoids unproved takeover, and mutates only through admitted emission paths.
- **Science and prerequisite qualification.** Generated research uses reachable, enabled science routes and rejects missing, cyclic, disabled, or unsafe dependencies.
- **Deterministic packages.** A single materializer creates package trees and archives from exact source bindings; player ZIPs exclude repository tooling, tests, fixtures, evidence, and governance files.
- **Actionable diagnostics.** Compiler and compatibility reports explain why a subject was emitted, preserved, skipped, or rejected.
- **Portable support evidence.** `SupportBundleV1` exports governed environment and diagnostic facts without treating raw local state as public proof.

Preview, shadow, and experimental architecture remains read-only or package-excluded unless a separate authority explicitly grants player behavior or release use. No blanket compatibility claim is inferred from discovery alone.

## Install or upgrade

Install MIR from the Factorio Mod Portal or download the target-specific ZIP from the project’s GitHub release. Place the ZIP in Factorio’s `mods` directory and leave it packed. Do not install GitHub’s automatically generated “Source code” archives: they contain repository material and are not valid MIR packages.

Keep the exact predecessor package until the upgrade has loaded, saved, and reloaded successfully. MIR’s supported transition is stated in the package README and release notes for each target. Back up important saves before changing Factorio, MIR, or a large mod set.

See [installation](docs/user/installation.md), [settings](docs/user/settings.md), and the [generated effective defaults](docs/reference/generated/stream-defaults.md).

## Compatibility and safety

MIR is conservative when ownership or behavior is uncertain. It does not silently reinterpret arbitrary Lua, and it does not mutate prototypes merely because another mod was discovered. Public compatibility statements are limited to named claim levels and exact evidence.

A governed subject receives an explicit outcome: generated by a certified path, preserved for another owner, held for review, or reported unsupported. Uncertainty cannot increase automation. Optional target features such as Space Age research are present only where the target and active mod set support them.

Read [compatibility claims](docs/user/compatibility-claims.md), [claim levels](docs/compatibility/claim-levels.md), and the [settings reference](docs/reference/settings.md).

## Diagnostics and support

Start with the in-game diagnostics and MIR log rows. When reporting a problem, include the MIR distribution version, Factorio version, enabled mod list, reproduction steps, and the smallest relevant log excerpt. If available, attach a redacted support bundle; inspect it before sharing because environment evidence can contain local paths or mod names.

Use [SUPPORT.md](SUPPORT.md) for the reporting route and [SECURITY.md](SECURITY.md) for private vulnerability disclosure. Do not post private saves, credentials, signing material, or unredacted machine paths in a public issue.

## Developer entry points

The repository root is not an editable Factorio package. Current player source lives under `src/mod`; target identity, policy, overlays, and target-owned files live under `targets`; the canonical materializer writes disposable output below `build/packages`.

The public command surface is:

```powershell
.\tools\mir.ps1 <area> <command>
```

Useful references include the [architecture overview](docs/architecture/README.md), [module boundaries](docs/architecture/module-boundaries.md), [generated runtime pipeline](docs/reference/generated/runtime-pipeline.md), [test guidance](docs/maintainer/testing.md), and [release runbook](RELEASE-RUNBOOK.md).

Before tests, inspect or materialize the MIR verification plan and run the narrowest selected proof. The broad package-excluded static fallback is:

```powershell
.\scripts\Invoke-MIRValidation.ps1 -StaticOnly
```

Factorio 2.1 testing uses the installed Steam experimental build. Historical engines live outside Steam and must not be downloaded, replaced, or retargeted without maintainer authority.

## Contributing

Read [CONTRIBUTING.md](CONTRIBUTING.md) and [AGENTS.md](AGENTS.md) before changing the repository. Ordinary work starts from the protected `dev` line. Preserve one authority per fact, regenerate projections from their source authorities, keep package contents clean, and attach proof to exact inputs.

Documentation under `docs/` uses governed front matter. Generated indexes, dashboards, catalogues, pipeline tables, and default tables must be regenerated by their owning commands rather than edited directly. Historical release records are custody inputs and remain byte-stable.
